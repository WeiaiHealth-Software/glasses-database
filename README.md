# 📄 近视防控镜片查询系统需求 PRD 文档

## 一、 产品概述

### 1\.1 产品定位

本产品是一个**纯工具类**的近视防控镜片参数查询数据库系统。深度绑定微信公众号，作为公众号的核心工具性功能。

- **核心身份**：专业检索工具。

- **目标用户**：眼科医生、视光医师、眼镜验光师（专业端）；近视儿童家长（大众端）。

- **三条底线（极其重要）**：不提供诊疗、不承诺疗效、不售镜（无交易、无商城、无付费）。

### 1\.2 核心业务目标

- 提供专业、客观的镜片参数查阅与横向对比。

- 提供通俗易懂的科普解读。

- 实现零门槛的表单化数据维护与长期更新。

## 二、 用户端（微信小程序）功能需求

### 2\.1 启动与全局机制

- **强制免责弹窗**：

  - **触发机制**：用户首次打开小程序，或清除缓存后首次打开，必须强制弹出。

  - **交互规则**：声明文字固定，**不可跳过**。用户必须点击【已阅读并同意】方可进入首页。

- **全局免责常驻**：所有页面底部及详情页，需自带小字免责声明常驻。

- **全局分享**：支持分享给微信好友、分享到朋友圈。

### 2\.2 首页 \(Home\)

- **顶部搜索区**：大搜索框，支持品牌、镜片名、系列的模糊搜索、拼音搜索及部分字符匹配。

- **快捷筛选入口**：提供品牌、镜片类型、离焦类型、现货/定制的快捷筛选按钮。

- **双引流板块**：

  - **专家解说**：后台手动置顶推荐内容。

  - **论文参考**：按录入时间倒序排列展示。

- **信息流卡片展示**：品牌 \+ 镜片名称 \+ 核心标签（如：多点离焦、高离焦量、现货款）。

### 2\.3 检索与高级筛选 \(Search \& Filter\)

支持六大维度自由组合、多选筛选：

1. **品牌**：按品牌名称多选。

2. **技术类型（8类）**：多点离焦、环带微柱镜、蜂窝点阵、周边离焦、渐进多焦点、双光棱镜、OK镜、离焦软镜。

3. **离焦量区间**：按数值区间滑动或勾选筛选。

4. **是否现货（2类）**：现货镜片、定制镜片。

5. **适配最大散光区间**：按散光度数上限筛选。

6. **适配年龄区间**：按适用年龄范围筛选。

### 2\.4 镜片详情页 \(Detail\)

- **双模式平滑切换**：提供【家长通俗版】与【医生专业版】无刷新、平滑切换。通俗版文字柔和易懂，专业版参数规整严肃。

- **参数展示**：全量展示基础信息、核心参数及临床铁律。

- **操作区**：加入对比（最多4款）、加入收藏、转发分享。

### 2\.5 横向对比工具 \(Compare\)

- **核心功能**：支持勾选 2–4 款镜片进行同屏较量，自动生成全参数横向对比表格。

- **自适应与截图**：表格自动适配手机屏幕，支持长按生成友好布局的长图分享。

- **灵活编辑**：支持在对比页直接移除单个产品，或重新选择替换。

### 2\.6 个人中心与知识库 \(User \& Knowledge\)

- **我的收藏**：与微信用户身份绑定，一键留存高频常用镜片。

- **知识文库 \(V1\.1\)**：镜片知识点文库、热门问题问答库 \(FAQ\)。

- **系统说明**：使用说明、关于本工具、免责声明完整版。

## 三、 B端后台管理系统需求 \(PC端\)

B端管理系统是整个数据底座的核心，所有模块均需遵循标准化的\*\*增删改查（CRUD）\*\*逻辑，确保系统的高效维护与数据流转。

### 3\.1 镜片核心数据管理模块

本模块用于管理小程序端展示的所有镜片产品数据。

- **【查】多维检索与列表**：支持按品牌、技术分类、上架状态、创建时间等条件进行组合查询；列表页需展示镜片主图、名称、品牌、状态及更新时间。

- **【增】表单化录入**：提供全字段的标准化录入表单（涵盖基础信息、专业参数、临床铁律等近30个字段），支持上传参考白皮书/文献附件。

- **【改】数据编辑与状态流转**：

  - 支持对已录入的镜片数据进行全字段修改。

  - 支持一键“上架/下架”状态切换。

- **【删】数据移除**：支持对废弃或错误录入的镜片进行删除（建议采用软删除机制，保留底层数据以防误删）。

### 3\.2 字典与分类管理模块

用于维护系统中的筛选项基准数据，确保前端筛选维度的统一性。

- **【查】字典列表**：分类查看品牌库、技术大类库、膜层配置库等。

- **【增】新增配置**：动态添加新品牌名称、新的技术类型标签等。

- **【改】编辑配置**：修改已有标签名称，调整标签在前端筛选面板中的排序权重。

- **【删】移除配置**：删除不再使用的品牌或标签（需校验是否有关联的镜片数据，若有则禁止删除或提示转移）。

### 3\.3 首页运营与推荐管理模块

用于控制小程序首页的流量分发与内容展示。

- **【查】推荐位列表**：查看当前首页“专家解说”、“热门镜片”板块的已推荐列表及当前排序。

- **【增】新增推荐**：从已上架的镜片库或文章库中，勾选并添加至首页推荐位。

- **【改】排序与替换**：手动调整推荐内容的展示顺序（置顶、上移、下移），或修改推荐语。

- **【删】取消推荐**：将内容从首页推荐位移除（不影响原数据，仅取消推荐状态）。

### 3\.4 内容与知识库管理模块 \(V1\.1\)

用于管理科普文章、FAQ及系统公告。

- **【查】内容列表**：按文章类型（科普/FAQ/公告）、发布状态、发布时间检索。

- **【增】富文本发布**：通过富文本编辑器新建图文并茂的科普文章、问答对或更新公告。

- **【改】内容编辑**：修改文章标题、正文内容、封面图，切换“显示/隐藏”状态。

- **【删】内容删除**：永久删除过时或错误的科普文章及公告。

### 3\.5 系统设置与权限管理模块

- **【查】日志与账号**：

  - **操作日志**：只读查看所有后台账号的登录、新增、修改、删除等操作留痕（精确到时间、操作人、操作对象）。

  - **账号列表**：查看当前拥有后台权限的管理员列表。

- **【增】新增管理员**：创建新的后台登录账号，分配初始密码。

- **【改】系统配置与账号编辑**：

  - **全局免责声明**：修改小程序端全局调用的免责声明文本内容。

  - **账号管理**：重置管理员密码、冻结/解冻管理员账号。

- **【删】移除管理员**：注销或删除离职人员的后台账号权限。

## 四、 数据库与字段设计规范 \(数据底座\)

数据库必须严格按照以下维度建立产品全貌表结构：

### 4\.1 基础信息维度 \(5项\)

1. **基础标识**：镜片完整名称、品牌名称、产品系列、上市年份。

2. **技术大类**：多点离焦、周边离焦、渐进、双光、OK 镜、软镜。

3. **技术结构**：点阵离焦、环带微柱镜、蜂窝离焦、连续离焦。

4. **基材参数**：镜片基材、标准折射率。

5. **膜层配置**：标配膜层、可选升级膜层。

### 4\.2 专业核心参数 \(9项\)

1. **近视控制有效率**：需强制标注官方公布的数据及**数据来源**。

2. **离焦量 \(D值\)**：核心光学指标。

3. **中心光学区直径**：决定中心清晰视觉区与周边离焦区布局。

4. **离焦环数量**：表面离焦环/离焦点位数量。

5. *\(其余5项专业参数根据行业标准在开发期补齐\)*

### 4\.3 供货与适配画像

1. **供货属性**：现货镜片 / 定制镜片。

2. **定制支持**：常规订货周期、大散光定制支持、高度数定制支持。

3. **适配人群**：建议适配年龄区间、最佳适配近视度数区间、适配人群特征。

4. **禁忌症**：绝对禁忌症（不适合佩戴人群）、谨慎适配人群。

### 4\.4 临床验配铁律 \(6项 \- 核心壁垒\)

1. **验光原则**：足矫 / 常规足矫 / 特殊欠矫说明。

2. **双眼视功能**：明确双眼视功能适配要求。

3. **佩戴时长**：全天佩戴 / 日间佩戴。

4. **初次适应期**：列明初次适应期常见症状。

5. **加工装配误差**：明确加工装配误差要求。

6. **复查周期**：给出复查周期建议。

### 4\.5 价格与管理留痕字段

1. **价格展示**：官方建议零售价（单副），必须带备注“市场浮动、仅供参考”。

2. **资料来源**：品牌白皮书 / 临床文献存档（支持附件或链接）。

3. **后台管理字段**：是否首页推荐、排序权重、上架状态、创建时间、更新时间。

## 五、 开发红线与非功能性规范

### 5\.1 绝对禁止事项（五条红线）

1. **禁止交易**：严禁出现任何交易、付款、商城、团购功能。

2. **禁止绝对词**：严禁出现疗效排名、“最好”、“第一”等违反广告法的绝对表述。

3. **禁止承诺**：严禁私自承诺防控效果。

4. **禁止引流**：严禁留商家联系方式、广告、引流线下门店。

5. **数据只读**：所有前端展示数据仅为客观陈列，无主观评级，用户不可修改。

### 5\.2 UI/UX 设计规范

- **整体风格**：医疗工具风。专业、干净、不花哨，保持克制。

- **主色调**：护眼浅蓝 / 青绿色（契合视光行业调性）。

- **字体**：采用系统默认清晰字体，保证各年龄段可读性。

- **排版要求**：表格对比需清晰分明，留白合理，适合截图分享；科普文字需柔和，专业参数需规整严肃。

### 5\.3 交付与验收标准

1. **完整小程序**：前端代码完整，可直接提交微信审核上线。

2. **后台系统**：完整可用的 PC 端后台管理系统（含完整 CRUD 功能）。

3. **数据库**：完整的数据库表结构落地（提供 SQL 脚本）。

4. **生态配置**：协助完成公众号关联配置。

5. **交付物**：提供后台账号、部署说明文档、源码/低代码工程文件。
